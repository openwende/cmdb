# 主机流转规则

## 主机生命周期总览

一台主机的典型生命周期是：录入主机 → 导入资源池 → 分配到业务（落在空闲机）→ 转移到业务模块上线 → 使用期间可能在模块间转移、追加到别的模块、转入故障机修好后转回 → 转入待回收 → 回收到资源池。

审计里的归属变更只有四种类型：导入资源池、分配到业务、转移、回收到资源池。进出故障机、待回收，以及模块之间、资源池目录之间的移动，都记为"转移"。系统里还定义了"转入待回收"和"历史数据回填"两种类型，但实际操作从来不会产生"转入待回收"；要找主机什么时候进了待回收，看 to 为"业务 / 待回收"的转移记录。

## 录入主机和导入资源池

录入（新建）主机只是在 CMDB 里登记这台机器，审计里是一条 create 记录，config 里是录入时的配置；录入本身不会把主机放进任何地方，此时主机"无归属"。

导入资源池是把已录入的主机放进资源池的某个目录，审计类型"导入资源池"。已经在业务模块里的主机不能导入，会报"已分配到业务，请先回收"。已经在资源池里的主机再次导入，效果相当于换目录。

## 分配到业务

分配是把资源池里的主机交给某个业务。界面上的操作是"分配到业务空闲机池"，主机落到该业务的空闲机模块，同时离开资源池。审计类型"分配到业务"，from 为"资源池 / 目录名"，to 为"业务 / 空闲机"。分配之后通常还要再做一次转移，把主机从空闲机转到具体的服务模块，才算投入使用。

## 转移到业务模块

转移是把主机从当前模块移到另一个模块。界面上的操作是"转移至"→"业务模块"（或"空闲机池"下的空闲机、故障机、待回收）：主机从当前所在的模块移出，加入目标模块；主机如果还在其他模块里，那些归属保持不变。后端也允许把资源池里的主机直接转移到业务模块（跳过分配），主机会同时离开资源池。

审计类型"转移"，from 是转移前的全部归属，to 是转移后的全部归属。例如一台只在"订单服务"的主机转到"故障机"，记录为 from "业务 / 订单服务"、to "业务 / 故障机"。

## 追加到业务模块

追加是让主机在保留现有模块的同时，再加入一个模块。界面上的操作是"追加至"→"业务模块"，后端调用转移接口但不指定源模块：主机现有的业务模块归属全部保留，只去掉它在空闲机里的归属（如果有），再加入目标模块。

追加在审计里同样记为"转移"。区分追加和普通转移要对比 from 和 to：例如 from "业务 / 模块A"、to "业务 / 模块A、模块B"，说明是新增了模块B，主机并没有离开模块A，不能理解为"从模块A转出"。

## 转入故障机和待回收

把主机转入故障机或待回收，界面上是"转移至"→"空闲机池"，选择故障机或待回收。这和转移到业务模块完全一样：从当前模块移出、加入目标模块，审计类型"转移"。主机如果同时在多个模块，只会从当前操作的那个模块移出，其他模块的归属仍在。

转入故障机后的状态修改、修好后转回原模块，转入待回收后由平台回收，这些约定流程见《拓扑与空闲机池》的"故障机模块"和"待回收模块"。

## 回收到资源池

回收是把主机从业务退回资源池，审计类型"回收到资源池"，to 为"资源池 / 目录名"。界面上有两种操作会产生回收：

1. 业务拓扑页"转移至"→"主机池"（确认框标题是"确认归还主机池"）：选择要放入的资源池目录，调用回收接口。界面只在选中的主机都在空闲机池（空闲机、故障机、待回收）里时才允许这样操作，并提醒"请务必确认业务进程已停止或主机处于关机状态"。
2. 业务拓扑页"移出"→"当前模块"：调用 transfer-to-pool 接口，主机进入资源池的默认目录。

两种方式效果相同：主机在所有业务里的全部模块归属都会被删除，而不只是当前模块，然后主机进入资源池。界面"移出"页面上的提示写的是"当主机仅属于当前模块时，移除后将主机会默认放置于空闲机中"，和实际行为不符：实际是回收到资源池默认目录。界面上"归还到资源池"和"回收到资源池"是同一种操作的两种叫法。

## 界面限制和后端行为的区别

界面上的一些规则只是前端限制，后端接口并不检查：

- "主机需在空闲机池下才允许转移至主机池"：只是界面限制。直接调用回收接口时，不在空闲机池的主机也能被回收。
- "主机需在空闲机池下才允许转移至其他业务"：界面没有提供跨业务转移的入口；后端转移接口不检查目标模块所属的业务。
- 分配时界面只让选"业务空闲机池"，但后端分配接口不检查目标是不是空闲机模块。

所以审计里出现"不符合界面规则"的记录（例如主机还在业务的服务模块里就被回收），说明操作绕过了界面，或者界面以外的调用方式没有做检查，而不是数据出错。

## 后端不做的校验

以下情况后端都不拦截，可能在数据里出现：

- 回收不检查主机是否在待回收，也不检查主机是否还在其他模块。回收会删掉主机所有的业务模块归属，所以一台同时在多个模块、甚至还在正常服务模块里的主机，也会被一次回收直接退回资源池，其他模块里的归属一起消失。
- 分配不检查主机是否在资源池里。分配会删掉主机原有的全部归属，只留下目标模块，所以对已在业务里的主机执行分配，等于把它从原来的所有模块挪走。
- 资源池内换目录不检查主机是否在资源池里。对业务里的主机执行这个操作，会把它直接拉回资源池。
- 转移不检查目标模块是否和主机现有的模块同属一个业务，主机可能因此跨两个业务。
- 导入和回收接口可以带"备注"（remark），但备注不会保存，审计里也没有。

这些情况在审计里都有完整的前后归属，可以据此还原经过；但审计不记录操作原因，是否有意为之需要找操作人确认。
