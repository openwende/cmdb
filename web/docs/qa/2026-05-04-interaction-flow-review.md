方式：浏览器真实点击、DOM 快照、可视检查、前端控制台日志、后端容器日志。未使用 `cur`/`curl`。

- 资源目录：业务列表、新建业务抽屉、空提交校验、主机资源三个 Tab、导入主机抽屉。

## 优先级问题

### P1 - 窄视口下全局导航不可达

在移动宽度下，顶部只剩汉堡按钮，但点击后打开的是当前模块二级侧栏。例如在 `/resource/business` 中只能看到“业务列表 / 主机资源”，看不到“首页 / 业务拓扑 / 资源类型 / 审计与分析 / 用户管理”。

影响：用户进入某个模块后无法发现或切换到其他一级模块，只能依赖 Logo 回首页或直接知道 URL。

建议：移动端汉堡先承载全局导航，二级导航放入当前模块区域；或提供全局/模块两级明确切换。

### P1 - 业务拓扑右侧工作区在窄宽度下严重压缩

`/business/1000/topology` 中左侧拓扑树占据固定宽度，右侧主机列表和节点信息被挤压：

- 主机表格只显示局部列，空状态和搜索区缺少有效引导。
- “节点信息”详情值被挤到右侧，日期和人员字段断行，阅读成本高。
- 左右分隔拖拽柄视觉上很明显，但用户不知道能否调整。

影响：业务拓扑是核心动线，但在常见窄屏/分屏状态下不可读。

建议：为拓扑树设置可折叠默认状态；右侧面板使用最小宽度和横向滚动，节点信息改为单列详情；对拖拽柄增加 hover/tooltip。

### P1 - 主机资源和审计筛选区域出现水平裁切/重叠

`/resource/host` 的操作栏和表格在当前宽度下右侧被裁切，搜索框和表格列超出可视区域。`/analysis/audit` 的业务 Tab 中，日期范围和“账号”标签发生贴靠/重叠，“查询”按钮一度被挤到视口外。

影响：用户无法稳定完成搜索、筛选、分配/转移等高频操作。

建议：筛选区使用响应式换行栅格；表格长字段使用省略+复制/详情，不直接换成多行 UUID；操作按钮区域固定在可视宽度内。

### P1 - 模型字段定义与实例创建表单不一致

在 `QA测试服务器` 的“字段设计”Tab 中显示“该类型暂无属性定义”，但点击“创建实例”后，表单出现 `CPU核数`、`主机名`、`IP地址` 等字段。

影响：用户会认为模型没有字段，却在实例创建时被要求填写额外字段，破坏模型驱动实例表单的心智。

后端证据：后端日志出现 `GET /api/v1/dynamic-models/qa_server/schema` 404，`dynamic_models.uid = 'qa_server'` record not found。

建议：统一 `/api/v1/models` 与 `/api/v1/dynamic-models` 的模型标识来源；字段设计页和实例表单必须使用同一 schema。

### P2 - 资源类型详情页信息重复且含内部研发文案

模型详情页顶部摘要表和“基本信息”表重复展示大量字段。字段设计页出现“下一轮”“拖拽布局、字段分组和联合唯一规则放到下一轮”等研发计划文案；实例列表说明里出现“降级为类型详情里的次级能力”。

影响：面向用户的页面暴露内部迭代语言，削弱产品可信度；重复信息拉长主流程。

建议：保留一个摘要区和一个详情区；将研发计划文案替换为用户能理解的能力边界和下一步操作。

### P2 - 运营概览图表数据与真实指标不一致

顶部指标显示当前主机总数为 `6`、实例总数为 `0`，但图表中出现 Linux `156`、Windows `42`、业务柱状图上百数量等明显演示数据。

影响：统计页混合真实指标和 mock 图表，会误导运营判断。

建议：图表接入同一统计源；未接入时明确标注“示例数据”或隐藏该图表。

### P2 - 空状态缺少就地下一步

多个核心空状态只显示“暂无数据”：

- 业务列表空状态没有“新建业务”就地 CTA。
- 业务拓扑主机列表空状态没有“导入主机 / 分配主机”的解释。
- 审计空状态没有说明当前筛选条件或引导清空筛选。

影响：用户知道没有数据，但不知道下一步该做什么。

建议：空状态按场景补充主操作和原因，例如“当前业务没有模块，先创建集群/模块后再导入主机”。

### P2 - 禁用按钮缺少原因

业务拓扑和主机资源页中有大量禁用按钮：`新增`、`分配到`、`转移到`、`追加至`、`复制`。当前只呈灰态，没有 tooltip 或上下文说明。

影响：用户无法判断是权限不足、未选中数据、节点类型不支持，还是没有数据。

建议：禁用按钮统一提供 tooltip，并按状态拆分原因。

### P3 - 控制台警告和错误会污染 QA

前端控制台记录：

- `[rc-collapse] children will be removed`
- `[antd: message] Static function can not consume context`
- `[antd: Spin] tip only work in nest or fullscreen pattern`
- `[antd: Descriptions] Sum of column span...`
- 字段/实例/用户表单处出现未结构化 `Object` error

影响：短期不阻断用户，但会降低 QA 信噪比，也提示组件用法和错误处理需要收敛。

建议：升级相关组件写法；统一 `useAppMessage`；错误日志输出业务上下文和 message，避免裸 `Object`。

## 可用性亮点

- 首页在创建业务后能把主 CTA 从“创建/选择业务”切换为“进入业务拓扑”。
- 新建业务、新增属性、创建实例、新增用户的必填校验都能出现，基础表单防呆存在。
- 资源类型总览的分组筛选、卡片列表和详情入口清晰。
- 主机导入流程有步骤条、模板下载和文件大小提示，主线结构可理解。
