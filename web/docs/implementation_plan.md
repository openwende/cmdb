# 业务拓扑 / 主机列表页 — 产品与界面重设计方案

## 1. 当前页面问题分析

### 1.1 UX 视角：信息断裂和操作断层

**业务切换被埋在 Sidebar 里，上下文断裂。**
当前 `BusinessSelector` 作为一个普通 `<Select>` 藏在左侧 Sidebar 的顶部（`Sidebar/index.tsx` L232）。它和拓扑树属于不同的组件层级——Sidebar 是全局 Layout 的一部分，拓扑树是页面级组件。用户在页面内操作拓扑时，切换业务需要视线跳到一个完全不同上下文的区域。更严重的是：当 Sidebar 折叠（tablet 模式）时，业务名称完全不可见，用户丢失了"我在哪个业务"的感知。

**"当前节点"信息表达太弱。**
当前 `topology-panel__header` 区域只有三行文字（eyebrow + title + description），视觉分量等同于一个段落说明，而不是操作上下文的锚点。用户在频繁切换树节点时，右侧标题区没有足够的视觉重量来确认"我选的到底是哪个节点"。

**从"选节点"到"做操作"之间缺少过渡。**
选中节点后直接看到一排按钮，没有任何上下文提示"你将对 XX 模块做以下操作"。用户需要自行记忆选择结果。

### 1.2 信息架构视角：三个区域各说各话

当前页面的信息架构可以画成：

```
┌──────────────────────────────────────────────────────┐
│ Global Header                                        │
├──────┬───────────────────────────────────────────────┤
│      │                                               │
│ Side │  Business Selector (被藏在这里)                 │
│ bar  │                                               │
│      ├───────────────────────────────────────────────┤
│ Menu │  ┌──────────┐  ┌──────────────────────────┐   │
│      │  │ Topo Tree│  │ Panel Header             │   │
│      │  │ (搜索+树) │  │ Tabs: 主机|服务实例|节点  │   │
│      │  │          │  │ Toolbar (7+ buttons)     │   │
│      │  │          │  │ Table                    │   │
│      │  └──────────┘  └──────────────────────────┘   │
└──────┴───────────────────────────────────────────────┘
```

问题在于：

1. **Sidebar 和 Topo Tree 是两层导航**，但视觉上没有区分——左边有 sidebar menu + business selector，再右边又有一棵树。用户一眼看过去不知道 sidebar 和 tree 的职责区别。
2. **Panel Header 和 Tabs 是两个连续但不同的信息层**。eyebrow/title/description 是"上下文描述"，Tabs 是"功能切换"，但它们视觉上紧挨在一起，没有层级差异。
3. **Tree 区域没有头部信息**。只有一个搜索框，用户不知道这棵树代表的是哪个业务的拓扑。

### 1.3 视觉层级视角：没有节奏、没有重点

**扁平化严重。** 整个页面从左到右全是白色无背景容器，唯一的视觉断点是树和 panel 之间一条细细的 `border-right`。缺乏"区域-容器-元素"三层视觉层级。

**Toolbar 堆叠。** HostList 的操作栏有 7 个按钮（新增、编辑、转移到、追加到、移除、复制、更多）+ 搜索框，全部用相同的灰色 Button 平铺在一行，主次不分。唯一的主按钮"新增"也只是颜色不同而已。

**标题区缺乏锚点效果。** `font-size: 16px` 的标题、`font-size: 12px` 的 eyebrow、`font-size: 13px` 的 description 放在一起，视觉节奏差距太小，无法形成"这是当前工作区域入口"的感知。

**表格上下大量留白。** 操作栏和表格之间只有 16px 间距，表格底部的 pagination 和页签切换时的状态变化缺乏视觉过渡。

### 1.4 交互效率视角：高频操作成本不低

**一次完整操作的点击路径：**
1. 切业务：点 sidebar selector → 选业务 → 等 tree 刷新 → 选节点（4 步）
2. 转移主机：在 tree 选节点 → 勾选主机 → 点"转移到"→ 选目标 → 确认（5 步，跨越整个屏幕宽度）
3. 查看节点信息：选树节点 → 点"节点信息"tab → 等加载（3 步，但 tab 切换会失去列表筛选状态）

**搜索范围不清晰。** 树的搜索和列表的搜索位于不同区域，用户容易混淆"搜拓扑节点"和"搜主机 IP"。

## 2. 改版方向

### 方向 A：控制台工作台（Console Workstation）

**核心特征：**
- 页面上半部分是一条重量级的 **上下文横条**（Context Bar），包含：当前业务（可切换）+ breadcrumb 路径 + 关键统计数字
- 左侧 tree 作为 **导航抽屉**（可收起），和 sidebar 合并为一个统一的导航面板
- 右侧工作区去掉 panel header，由 Context Bar 完全承担上下文表达
- 工具栏做成 **工具面板**，按操作分组

**适合理由：**
- 业务切换和节点路径在同一条横线上，视觉锚点极强
- 适合 "横向宽屏 + 多任务" 的桌面端运维场景
- 统计数字天然适合 CMDB 场景（主机数 / 模块数 / 异常数）

**风险和取舍：**
- Context Bar 占据高度较多（~60-80px），在 ≤1080p 屏幕上压缩内容区
- 业务切换和 tree 导航放在不同层级，交互模式变化大
- 改动量大：需要同时重构 Sidebar + Header + TopologyView + BusinessTree

---

### 方向 B：资源运营面板（Operations Dashboard）

**核心特征：**
- 整体走 **面板分区** 风格：每个区域是一个有明确边界的面板（Panel）
- 树 panel 有自己的标题栏（显示业务名+切换按钮），工作区 panel 有自己的标题栏（显示当前节点+操作）
- Tab 下沉到工作区内部，toolbar 按语义分组并使用 icon button
- 底部有一条 **状态栏**（Status Bar），显示选中数、当前筛选条件

**适合理由：**
- 各区域职责清晰，学习成本低
- 对现有代码结构改动最小（主要是加包装 + 调样式）
- 天然适合多 tab 场景（主机列表 / 服务实例 / 节点信息各自独立面板）

**风险和取舍：**
- 面板边界过多可能让页面看起来"分裂"，缺乏整体感
- 状态栏占底部空间
- 如果不处理好面板间距和阴影，容易变成"卡片拼贴"风格

---

### 方向 C：专业拓扑操作台（Topology Workstation）

**核心特征：**
- 业务切换做成树区域的 **头部下拉**——树的最上方就是当前业务名，点击即切换。树和业务在信息架构上合并为一个整体："业务拓扑导航"
- 右侧工作区上方是一条 **轻量上下文条**（Node Context Strip），只显示"节点名称 + 节点类型 badge + 路径 breadcrumb"——不做大块 header，而是做精准的上下文锚点
- Tab 栏和 toolbar **合并为一行**：左边是 tab 切换，右边是当前 tab 对应的操作组
- 表格容器有微妙的 **容器包裹感**（非阴影卡片，而是背景色差异 + 圆角边界）
- 批量操作独立为 **底部浮现操作条**（Floating Action Bar），选中行后从底部滑出

**适合理由：**
- 专为"左树右表 + 高频切换节点 + 高频批量操作"的 CMDB 场景定制
- 业务和拓扑在认知上是一体的（"我在看 XX 业务的拓扑"），放在一起最自然
- 底部操作条只在选中时出现，平时不占空间，兼顾信息密度和操作效率
- tab/toolbar 合并后节省一行高度，表格区域更大

**风险和取舍：**
- 底部浮现操作条需要处理和 pagination 的位置关系
- 业务切换放在树区域意味着需要重构 `BusinessSelector` 的挂载位置
- Tab + toolbar 合并行需要处理窄屏溢出

---

## 3. 推荐方案：方向 C — 专业拓扑操作台

推荐方向 C，以下是详细设计。

### 3.1 页面整体布局结构

```
┌─────────────────────────────────────────────────────────────┐
│ Global Header (保持不变)                                     │
├─────────────────────────────────────────────────────────────┤
│ Sidebar(保持)│ Page Content Area                            │
│              │ ┌────────────┬──────────────────────────────┐│
│              │ │            │ Node Context Strip           ││
│              │ │  Business  │ ┌──────────────────────────┐ ││
│              │ │  Topology  │ │ Tab Bar + Toolbar (一行)  │ ││
│              │ │  Navigator │ ├──────────────────────────┤ ││
│              │ │            │ │                          │ ││
│              │ │ ┌────────┐ │ │     Table / Content      │ ││
│              │ │ │Biz Head│ │ │                          │ ││
│              │ │ │(切换)  │ │ │                          │ ││
│              │ │ ├────────┤ │ │                          │ ││
│              │ │ │ Search │ │ │                          │ ││
│              │ │ ├────────┤ │ ├──────────────────────────┤ ││
│              │ │ │  Tree  │ │ │ Pagination / Status      │ ││
│              │ │ │        │ │ └──────────────────────────┘ ││
│              │ │ └────────┘ │                              ││
│              │ └────────────┴──────────────────────────────┘│
│              │                                              │
│              │ ┌──────────────────────────────────────────┐ │
│              │ │ Floating Action Bar (选中主机后浮现)      │ │
│              │ └──────────────────────────────────────────┘ │
└──────────────┴──────────────────────────────────────────────┘
```

**关键结构决策：**
- Sidebar menu 保持不变，仍然负责全局导航（首页/业务/模型/资源/分析）
- 拓扑树从"页面级裸组件"升级为"带头部的独立导航面板"
- 右侧工作区取消独立的 panel header 区域，改为紧凑的 Node Context Strip
- Tab 和 Toolbar 合并为一行，Tab 在左，Toolbar 在右
- 批量操作按钮组从常驻工具栏移出，改为选中后的底部浮现条

### 3.2 业务切换入口的位置和理由

**放在拓扑树面板的头部，作为树的"作用域声明"。**

具体设计：

```
┌──────────────────────┐
│ 🏢 ProbeSetBiz       │  ← 业务名称，点击展开业务切换下拉
│    #1773163724333    │  ← 业务 ID（次要信息）
│ ▾                    │  ← 下拉指示器
├──────────────────────┤
│ 🔍 搜索拓扑节点...    │
├──────────────────────┤
│ ▾ ProbeSetBiz (业务)  │
│   ▾ 空闲机池           │
│   ▸ ProbeSet-renamed  │
└──────────────────────┘
```

**理由：**
1. **认知一致性**：用户看到树时，第一个信息应该是"这是哪个业务的树"，业务名作为树的标题在"意义上游"
2. **操作就近性**：切换业务后树会刷新，把触发器和结果放在相同区域，用户不需要跨越屏幕
3. **空间效率**：利用了树区域顶部原本只有搜索框的空间，不额外占高度
4. **适配友好**：在窄屏/移动端，树变成抽屉时，业务切换自然包含在抽屉中

**切换组件设计细节：**
- 默认显示业务名 + 业务 ID（小字灰色）
- 点击展开一个 Popover/Dropdown，包含搜索 + 分组列表（业务 / 业务集）
- 最近使用的业务置顶
- 底部保留"新建业务"入口

### 3.3 左侧拓扑树改造

**从"裸树"升级为"拓扑导航面板"：**

```
┌── Topo Navigator ──────────────────────┐
│                                        │
│  ┌─ Business Header ────────────────┐  │
│  │ 🏢 ProbeSetBiz-1773163724333     │  │
│  │   业务 · 3 集群 · 5 模块 · 1 主机 │  │  ← 一句话概览统计
│  └──────────────────────────────────┘  │
│                                        │
│  ┌─ Search ─────────────────────────┐  │
│  │ 🔍 搜索节点名称...                │  │
│  └──────────────────────────────────┘  │
│                                        │
│  ┌─ Tree ───────────────────────────┐  │
│  │ ▾ 🟦 ProbeSetBiz               7│  │
│  │   ▾ ⬜ 空闲机池                  0│  │  ← 灰色标识系统节点
│  │     ⬜ 空闲机                    0│  │
│  │     ⬜ 故障机                    0│  │
│  │     ⬜ 待回收                    0│  │
│  │   ▸ 🟩 ProbeSet-renamed        1│  │  ← 绿色标识正常集群
│  └──────────────────────────────────┘  │
│                                        │
│  ◁ ──── drag handle ──── ▷            │  ← 可拖拽宽度
│                                        │
└────────────────────────────────────────┘
```

**改造要点：**

1. **Business Header 区域**
   - 业务名 + 业务 ID 作为标题，字号 15px，font-weight 600
   - 下方一行概览统计：`业务 · 3 集群 · 5 模块 · 1 主机`，用小标签样式
   - 整个区域可点击，展开业务切换
   - 有微妙的背景色（`var(--color-bg-spotlight)`），和搜索/树区分开

2. **树节点渲染增强**
   - 每个节点前的 prefix badge 改为圆角矩形 + 图标，不同节点类型不同颜色：
     - 业务节点：蓝色 `🟦`
     - 集群节点：绿色 `🟩`
     - 模块节点：橙色 `🟧`
     - 空闲机池/系统节点：灰色 `⬜`
   - 节点名略粗（medium），数字右对齐（text-tabular-nums），颜色偏灰
   - 选中节点不仅高亮背景，还在左侧有 3px 的蓝色指示条

3. **折叠/展开**
   - 折叠时：树区域变成 48px 窄条，只显示业务名首字母 + 展开按钮
   - 展开始终保持动画过渡（200ms）

### 3.4 右侧 Node Context Strip

取消当前的三行 header（eyebrow + title + description），替换为一条紧凑的上下文条：

```
┌─ Node Context Strip ──────────────────────────────────────────────┐
│                                                                   │
│  ┌────┐                                                           │
│  │ 模块 │  SmokeModule-1773163733771                   集群 ▸ 模块 │
│  └────┘  └─ 节点名称，18px semibold ─┘         └─ breadcrumb ─┘   │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

**设计细节：**

- **节点类型 Badge**：和树一致的颜色系统，圆角矩形，小号字体
- **节点名称**：18px、semibold、颜色 `var(--color-text-primary)`
- **路径 Breadcrumb**：右对齐，显示从业务到当前节点的路径，用 `>` 分隔，灰色文字
- 整行高度 52px，底部有 1px `border-bottom`
- 未选中节点时显示："请在左侧选择拓扑节点"（居中灰色文字）

### 3.5 Tab 栏和 Toolbar 合并设计

将当前的 Tabs + 独立 operation-bar 合并为一行：

```
┌─ Tab + Toolbar Row ──────────────────────────────────────────────┐
│                                                                  │
│  主机列表   服务实例   节点信息  │  🔍 搜索IP...    ⊕ 新增主机    │
│  ───────                       │                                │
│                                │                                │
└────────────────────────────────┴────────────────────────────────┘
```

**左侧 Tab 区域：**
- 保持三个 tab 不变：主机列表 / 服务实例 / 节点信息
- 使用 Ant Design Tabs 的 `type="line"` 样式
- Tab item 增加小号计数 badge（如：主机列表 · 12）

**右侧 Toolbar 区域（按 Tab 动态变化）：**

当 Tab = 主机列表 时：
```
🔍 搜索IP/主机名...     ⊕ 新增主机
```
- 搜索框：紧凑尺寸，240px 宽度，带清除按钮
- 新增主机：primary 按钮，只在模块节点时可用
- 只保留 **搜索 + 主操作**，其他操作下沉

当 Tab = 服务实例 时：
```
🔍 搜索...  [实例|进程]  ☐ 全部展开    ⊕ 新增
```

当 Tab = 节点信息 时：
```
（无 toolbar，直接展示信息）
```

### 3.6 批量操作设计：底部浮现操作条

**现有问题：** 7 个按钮平铺在工具栏，主次不分，大部分时候它们处于 disabled 状态却仍然占据空间。

**新设计：Floating Action Bar**

当用户在表格中选中 ≥1 行时，从页面底部滑出一个操作条：

```
┌─ Floating Action Bar ────────────────────────────────────────────┐
│                                                                  │
│  已选择 3 台主机    │  转移到...  │  追加到  │  移除  │  复制  │  更多  │  ✕ 取消  │
│                    │                                             │
└────────────────────┴─────────────────────────────────────────────┘
```

**设计细节：**
- **位置**：固定在工作区底部（不是全屏底部），`position: sticky; bottom: 0`
- **出现动画**：从底部 slide up + fade in，200ms
- **背景**：`var(--color-bg-elevated)` + `box-shadow: 0 -2px 8px rgba(0,0,0,0.08)` + 上边框
- **高度**：52px
- **左侧**：选中计数（蓝色数字加粗）
- **中间**：操作按钮组，按操作类型排列
  - 「转移到」「追加到」「移除」：这三个是位置操作，用默认按钮（outline 风格）
  - 「复制」「更多」：辅助操作，用纯文本按钮（text 风格）
- **右侧**：✕ 取消选择 按钮
- **按钮的 disabled 逻辑保持不变**，只是挪到了操作条内

> [!IMPORTANT]
> Floating Action Bar 和 Pagination 的位置关系：
> - Pagination 始终固定在表格下方
> - FAB 出现时覆盖在 Pagination 上方（z-index 更高）
> - FAB 消失后 Pagination 重新可见

#### 选中状态

表格选中行使用 `var(--color-primary-bg)` 背景（浅蓝），左侧 checkbox 列有微妙的蓝色竖条。

### 3.8 桌面端和窄屏适配策略

#### 桌面端 ≥ 1280px（主要场景）

- 完整布局：Sidebar 220px + Tree 320px + 工作区 flex-1
- 所有功能可见

#### 中宽屏幕 1024px – 1279px

- Sidebar 折叠至 60px
- Tree 依旧可见但默认宽度缩到 260px
- Tab + Toolbar 一行保持
- Floating Action Bar 按钮文字缩短

#### 平板 768px – 1023px

- Sidebar 折叠至 60px（icon-only）
- Tree 变成可收起的 overlay panel（点击按钮展开/收起，覆盖在工作区左侧）
- Tab + Toolbar 分成两行（Tab 一行，Toolbar 一行）
- Floating Action Bar 按钮只显示 icon + tooltip

#### 移动端 < 768px

- Sidebar 收起为 hamburger 菜单
- Tree 变成页面顶部的下拉选择器 + 抽屉触发器
  - 显示当前节点名称，点击打开全屏抽屉选择节点
- Tab + Toolbar 分离：
  - Tab 在上
  - Toolbar 折叠为 icon 按钮组
- 表格横向可滚动
- Floating Action Bar 全宽底部固定

### 4.1 组件拆分建议

| 新组件 | 路径建议 | 说明 |
|--------|---------|------|
| `TopoNavigator` | `BusinessTopology/TopoNavigator/` | 替代 BusinessTree，包含 BusinessHeader + Search + Tree |
| `BusinessSwitcher` | `BusinessTopology/TopoNavigator/BusinessSwitcher/` | 从 `BusinessSelector` 的逻辑中提取，改为 Popover 触发 |
| `NodeContextStrip` | `BusinessTopology/NodeContextStrip/` | 替代 `topology-panel__header` |
| `TabToolbar` | `BusinessTopology/TabToolbar/` | Tab + 右侧 Toolbar 的合并组件 |
| `FloatingActionBar` | `BusinessTopology/FloatingActionBar/` | 底部浮现操作条 |
| `NodeTypeBadge` | `components/common/NodeTypeBadge/` | 节点类型标签（业务、集群、模块等） |

### 4.2 保留现有逻辑、只重构 UI 的区域

| 区域 | 说明 |
|------|------|
| `TopologyTree` 组件的交互逻辑 | 节点选中、展开、hover 创建按钮、搜索过滤——这些逻辑保持不变，只调 `renderTitle` 的渲染方式 |
| `HostList` 的数据逻辑 | `fetchNodeHosts`、`adaptTopologyHost`、分页、选中——保持不变，只重构 JSX 结构和样式 |
| `BusinessSelector` 的 store 层 | `useBusinessStore` 的 `loadBusinessData`、`getBusinessById`、`setCurrentBusiness` 完全保持 |
| `ServiceInstance`、`NodeInfo` | 保持现有逻辑，只统一包装容器和 toolbar 样式 |
| 所有 Modal（AddHostModal / TransferHostModal / ReleaseHostModal / CreateNodeModal） | 完全保持不变 |

### 4.3 需要谨慎改动的交互

| 改动 | 风险 | 建议 |
|------|------|------|
| `BusinessSelector` 从 Sidebar 移到 Tree 头部 | Sidebar 中有 `isBusinessRelated` 判断，移出后需要同步调整 Sidebar 渲染逻辑 | 先在 `TopoNavigator` 中新建 `BusinessSwitcher`，然后再从 Sidebar 移除旧的 |
| Toolbar 按钮从常驻改为 Floating Bar | 涉及 `handleMenuClick`、所有 Dropdown 的挂载位置变化 | 先让 Floating Bar 渲染，保持相同的 onClick handler 引用 |
| Tab + Toolbar 合并 | Tabs 的 `tabBarExtraContent` prop 可以原生支持，但搜索框位置变化可能影响 `searchValue` 的 focus 行为 | 使用 Ant Design Tabs 的 `tabBarExtraContent={{ right: <Toolbar /> }}` |
